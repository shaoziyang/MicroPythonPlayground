# MicroPython Playground

> 一个基于 **WebAssembly** 的本地 MicroPython 交互式运行环境。代码全部在浏览器内编译执行，无需连接后端，打开即可用。

![版本](https://img.shields.io/badge/version-v2.6.77-brightgreen.svg) ![内核](https://img.shields.io/badge/kernel-MicroPython-blue.svg) ![License](https://img.shields.io/badge/license-MIT-lightgrey.svg)

一个单文件 HTML 应用，把 MicroPython 解释器（`micropython.wasm`）搬进浏览器，提供带语法高亮的编辑器、REPL 交互、两级示例库与贪吃蛇彩蛋。支持直接用 `file://` 双击打开，也支持部署到任意静态服务器或 PHP 环境。

## 使用说明

### 文件模式（file://）

直接双击 `index.html` 即可离线运行，无需服务器。

- 内核通过外置的 `micropython.bundle.js`（经典脚本，非 ESM）加载，规避了 Firefox / Edge / Chrome 对 `file://` 下 `import()` / `fetch()` 本地文件的 CORS 限制。
- 内核文件与主页面需放在**同一目录**。
- 知识库题库独立于 `KnowledgeBase.js`，与主页面同目录；替换该文件即可更新题库，无需改动 HTML。
- 更新功能在 `file://` 下会自动降级为**浏览器下载**：逐个尝试多个 CDN，成功即触发下载，不依赖 `update.php`。
- 浏览器禁用 `file://` 页面的 Cookie，因此主题、分区比例/方向、代码等配置改用 **localStorage** 保存，刷新后仍可恢复。
- PHP 版本显示为「不可用」（本地无服务端）。

### HTTP 模式

把全部文件放到任意静态服务器目录，访问 `index.html` 即可。

```bash
# Python 自带静态服务器
python3 -m http.server 8000
# 然后浏览器打开 http://localhost:8000/
```

- 内核通过 `module Worker` + 动态 `import()` 加载 `micropython.mjs` 与 `micropython.wasm`，运行更流畅。
- 若部署在 **PHP 环境**（保留 `update.php`），可使用服务端更新代理：由 PHP 多 CDN 回退抓取内核文件，绕开浏览器跨域限制；`update.php?probe=php` 用于探测 PHP 版本。

### REPL 历史命令持久化

REPL 中用 <kbd>↑</kbd>/<kbd>↓</kbd> 回溯的命令会持久化保存，刷新或重新载入页面后不丢失。默认保留最近 **50** 条；可在「选项」页的**保留 REPL 历史命令数量**中设置（范围 0–500，填 `0` 表示不保留并清空现有历史），保存后立即按新数量裁剪。历史与条数均存于 localStorage（file:// 下同样有效）。

### 本地 lib 映射为内核 /lib

与主页面同目录的 `lib/` 文件夹会被完整映射到 MicroPython 内核文件系统的 `/lib`，支持子目录包。内核启动后即可：

```python
import os
print(os.listdir('/lib'))          # ['greeting.py', 'constants.py', 'mypkg', ...]
import greeting
print(greeting.hello())            # Hello, MicroPython Playground!
from mypkg.utils import double
print(double(21))                  # 42
```

使用步骤：

1. 把自己的 `.py` / `.mpy` 模块放进 `lib/`（子目录即包，需带 `__init__.py`）。
2. 运行一次打包脚本刷新清单与 bundle：
   ```bash
   python3 make_lib_bundle.py
   ```
3. 刷新页面，终端会提示「已映射本地 lib → /lib（N 个文件）」。

机制：内核默认 `sys.path` 已含 `/lib`，页面启动时通过 `mp.FS.mkdir/writeFile` 把文件写入 wasm 文件系统（Worker 与主线程两种运行模式均已覆盖）。**HTTP 模式**按 `lib/manifest.json` 逐文件 `fetch`，因此日后只改模块内容无需重跑脚本、刷新即可；**file 模式**因浏览器 CORS 限制改由 `lib.bundle.js`（经典脚本）提供，增删文件后需重跑 `make_lib_bundle.py`。

### wasm /flash 持久化

内核文件系统的 `/flash` 目录会被整体序列化到 localStorage（键 `mp_flash_fs`），重载页面或点「重置内核」后自动恢复，因此可以把数据文件长期留在浏览器里：

```python
import os
os.mkdir('/flash/data')                       # 支持子目录
open('/flash/data/a.txt', 'w').write('你好')   # 文本
open('/flash/data/b.bin', 'wb').write(bytes([0, 1, 255]))  # 二进制
print(os.listdir('/flash/data'))              # ['a.txt', 'b.bin']
```

- 每次运行代码（含 REPL 单条命令）后自动回写快照；删除文件同样会同步，不会在重载后「复活」。
- 文件内容以标准 Base64 存入，二进制安全；空目录也会保留。
- 顶栏「检查更新 / 更新到本地 / 主题切换」三个按钮紧随「就绪」之后；主题按钮**只显示图标**，其后是布局切换与**文件列表开关**按钮；选项页仍保留主题切换按钮，两处状态同步。
- Worker 与主线程两种运行模式均已覆盖；若 localStorage 配额不足，终端会给出警告。

### 多文件编辑器与文件列表

- 内核启动后工作目录切到 `/flash`，相对路径 `open('x.py')` 即落在此处。
- **启动自动运行**：若 `/flash/main.py` 存在，页面加载 / 重建内核后会自动执行它（首次运行会用编辑器初始代码创建该文件）。
- **文件列表位于工作区最左侧**，纵向跨越编辑器与 REPL 全高；右侧的竖向分隔条可拖拽调整宽度（双击复位，宽度本地保存）。
- 列表显示当前目录内容：点击文件夹进入、左上角 `←` 返回上级；头部 `＋` 在当前目录**新建文件**（立即落盘），旁边的文件夹图标**新建文件夹**。
- **鼠标右键点击文件**弹出菜单：**新建文件夹**（在当前目录）、改名（同步已打开的标签）、删除、属性（大小 / 修改时间）、下载文件；**文件夹同样可改名 / 删除**（递归删除其中全部内容，自动关闭相关标签），但不能下载。文件列表项右侧的 `×` 可直接删除文件 / 文件夹。
- 编辑器支持多文件标签页，标签上的 `●` 表示未保存；文件名后紧跟**纯图标保存按钮**（SVG 严格居中、隐藏文字），在改动后可点、未修改时置灰，等价于 `Ctrl/⌘ + S`；`Ctrl/⌘ + Enter` 运行**当前标签文件**。
- 点击示例菜单会统一在 **`/flash/demo.py`** 中打开示例代码（复用同一文档，不会反复新建文件造成标签堆积），也不覆盖其它正在编辑的文件。
- 顶栏文件按钮可显示 / 隐藏左侧文件列表，状态本地保存。
- 文件列表分隔条与「编辑器 / REPL」分隔条**宽度统一**，风格一致，均可拖拽调整、双击复位。
- REPL 输入框提示包含 `↑/↓ 历史 · Ctrl-D 复位`；按 `Ctrl/⌘ + D` 执行**软复位**（重置内核、清空 Python 全局状态，类似 MicroPython REPL 的 Ctrl+D）；启动后仍会重新自动运行 `/flash/main.py`。
- 终端输出与代码区标记为**不可被浏览器翻译**，避免翻译插件把程序输出改成全角标点、出现"输出两次"的假象。
- 工具箱标签切换在 `<head>` 提前注册，**内核加载期间**也能立即切换到其它标签页。

### 数据导入 / 导出

选项页底部的「导出数据」与「导入数据」用于整体备份 / 恢复：
- **导出**：把所有 `mp_` / `mp-` 前缀的 localStorage 与 Cookie 参数（主题、标签样式、布局方向、文件列宽、REPL 历史及保留条数、打开的文档、各游戏进度、知识库总分等）连同 `/flash` 文件系统快照打包为 JSON 文件下载，文件名为 `mpy_toolbox_` + 日期 + `_` + 时间 + `.json`（如 `mpy_toolbox_20260101_123045.json`）。导出结果的提示卡片为全局组件，在任意标签页均可看到，并在 3 秒后自动消失。
- **导入**：校验备份格式后覆盖当前全部参数与 `/flash` 文件，二次确认并自动重新加载页面，使文件系统重新挂载生效。

### 右键菜单

整个页面已屏蔽浏览器原生右键菜单，按所在组件显示对应菜单：
- **文件列表**：新建文件夹、改名、删除、属性、下载文件（见上文）。
- **编辑框 / REPL**：撤销、重做、剪切、复制、粘贴、全选。
- **终端输出**：复制选中、复制全部输出、清空输出、聚焦输入。
- **文件标签**：打开、保存、关闭、关闭其他。
- **其他页面 / 组件**：复制选中文字、切换主题、显示 / 隐藏文件列表、切换布局、重新加载页面。

## 升级方式

应用提供两条升级通道：

**1. 检查并更新内核（推荐）**

- 点击工具栏「更新」按钮，程序会从 npm registry（含镜像）检测 MicroPython 内核最新版本。
- 确认后逐文件下载 `wasm` 与 `mjs`，HTTP 模式由 `update.php` 代理、file 模式由浏览器直接下载。
- 支持 4 个 CDN 自动回退：`jsdelivr`、`fastly`、`unpkg`、`jsdmirror`；若自动下载被拦截，还提供手动下载链接。

**2. 升级程序本体**

- 程序版本号集中在配置区的 `const APP_VERSION`（单一修改点），显示于「关于」框正文。
- 请到 [GitHub](https://github.com/shaoziyang/MicroPythonPlayground) 或 [Gitee](https://gitee.com/shaoziyang/MicroPythonPlayground) 下载最新版主页面，替换旧文件即可。

> 配置区位于文件末尾，集中了 `APP_VERSION`、`SAMPLE_GROUPS`（示例菜单）、`USEFUL_LINKS`（常用链接），修改后刷新页面即生效，无需改动其它代码。

## WorkBuddy 开发过程

本项目由 **WorkBuddy** 持续迭代开发，版本从 0 开始，逐步演进至 `v2.6.77`。主要里程碑：

1. **界面与主题**：关于框样式、署名与跳转、GitHub/Gitee 按钮、明暗主题切换、主题按钮去文字化。
2. **信息框增强**：点击图标/标题打开、显示内核与 PHP 版本、WorkBuddy 品牌署名、内嵌贪吃蛇、`ℹ️` 改 `💬`。
3. **离线适配**：图标改 data URI 内联，解决 `file://` 下图标不显示；更新在 file 模式降级为下载。
4. **内核加载重构**：因 Firefox / Edge 在 `file://` 下报 `Failed to fetch dynamically imported module`，放弃内联方案，改为外置经典脚本 bundle（`micropython.bundle.js`），file 模式用经典 Worker + `importScripts()`，HTTP 模式用 module Worker。
5. **示例**：示例库从最初的几个例子扩充到 15 个分类、100 多个可直接运行的程序，按类别浏览、一键载入。
6. **常用链接**：整理官网、文档、固件下载、中文社区等常用网址，放进下拉菜单，点一下即可打开。
7. **贪吃蛇打磨**：署名文字与配色、CELL 自适应、食物数量/定时/上限、抗 Edge rAF 节流的独立定时器、手动/自动双主题配色、修复跨色系渐变导致的「混色」问题。
8. **小游戏模式**：大屏下拉框切换，**数字键 1-9 快速切换序号 1-9 的游戏**（序号连续无缺漏，10~16 仅从下拉框选择）；退出大屏会记住当前模式，刷新页面后也能恢复上次选择的小游戏，小游戏仅大屏可用。游戏名称与快捷键：

### 版本号规则

格式为 `主版本.次版本.build`，单一修改点为配置区 `const APP_VERSION`（显示在「关于」框）。

| 段     | 名称      | 递增规则                                  |
| ----- | ------- | ------------------------------------- |
| 第 1 位 | 主版本号    | **人工指定**，仅在明确要求时变更，不自动递增              |
| 第 2 位 | 次版本号    | 本轮有**较大功能增加**时 +1，否则不变                |
| 第 3 位 | build 号 | **每次修改都 +1**；主版本 / 次版本变化时**不归零**，继续累加 |
