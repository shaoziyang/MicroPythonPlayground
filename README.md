# MicroPython Playground

> 一个基于 **WebAssembly** 的本地 MicroPython 交互式运行环境。代码全部在浏览器内编译执行，无需连接后端，打开即可用。

![版本](https://img.shields.io/badge/version-v2.7.85-brightgreen.svg) ![内核](https://img.shields.io/badge/kernel-MicroPython-blue.svg) ![License](https://img.shields.io/badge/license-MIT-lightgrey.svg)

一个单文件 HTML 应用，把 MicroPython 解释器（`micropython.wasm`）搬进浏览器，提供带语法高亮的编辑器、REPL 交互、两级示例库与贪吃蛇彩蛋。支持直接用 `file://` 双击打开，也支持部署到任意静态服务器或 PHP 环境。

## 使用说明

### 文件模式（file://）

直接双击 `index.html` 即可离线运行，无需服务器。

- 内核通过外置的 `micropython.bundle.js`（经典脚本，非 ESM）加载，规避了 Firefox / Edge / Chrome 对 `file://` 下 `import()` / `fetch()` 本地文件的 CORS 限制。
- 内核文件与主页面需放在**同一目录**。
- 知识库题库独立于 `KnowledgeBase.js`，与主页面同目录；替换该文件即可更新题库，无需改动 HTML。
- 更新功能在 `file://` 下会自动降级为**浏览器下载**：逐个尝试多个 CDN，成功即触发下载，不依赖 `update.php`。
- 浏览器禁用 `file://` 页面的 Cookie，因此主题、分区比例/方向、代码等配置改用 **localStorage** 保存，刷新后仍可恢复。
- PHP 版本显示为「不可用」（本地无服务端）。

### HTTP 模式

把全部文件放到任意静态服务器目录，访问 `index.html` 即可。

```bash
# Python 自带静态服务器
python3 -m http.server 8000
# 然后浏览器打开 http://localhost:8000/
```

- 内核通过 `module Worker` + 动态 `import()` 加载 `micropython.mjs` 与 `micropython.wasm`，运行更流畅。
- 若部署在 **PHP 环境**（保留 `update.php`），可使用服务端更新代理：由 PHP 多 CDN 回退抓取内核文件，绕开浏览器跨域限制；`update.php?probe=php` 用于探测 PHP 版本。

### REPL 历史命令持久化

REPL 中用 `↑`/`↓` 回溯的命令会持久化保存，刷新或重新载入页面后不丢失。默认保留最近 **50** 条；可在「选项」页的**保留 REPL 历史命令数量**中设置（范围 0–500，填 `0` 表示不保留并清空现有历史），保存后立即按新数量裁剪。历史与条数均存于 localStorage（file:// 下同样有效）。

### 内核文件系统：挂载到根目录 /

页面默认把 MicroPython 内核文件系统的**根目录 `/`** 作为工作根目录。内核启动后会自动创建 `/flash` 与 `/lib` 两个用户目录，并将二者加入 `sys.path`（Worker 与主线程两种模式均已覆盖），因此可以直接 `import` 自己放进这两个目录的模块：

```python
import os, sys
print(os.listdir('/'))             # ['flash', 'lib', ...]
print(sys.path)                    # ['', '.frozen', '/lib', '/flash', ...]
open('/lib/mymod.py', 'w').write('VALUE = 42')
import mymod
print(mymod.VALUE)                 # 42
```

文件列表默认展示根目录 `/`，可逐级进入任意子目录，也可在**根目录直接新建文件 / 文件夹**；相对路径 `open('x.py')` 落在当前工作目录 `/`。根目录下内核自带的 `tmp` / `home` / `dev` / `proc` 四个虚拟或临时目录**不予显示**（它们无法直接使用），其他层级不受影响。

### wasm 文件系统持久化

整个内核文件系统会被序列化到 localStorage（键 `mp_flash_fs`）——涵盖 `/`、`/flash`、`/lib` 及其中新建的文件 / 文件夹，仅排除 `/dev`、`/proc`、`/tmp`、`/home` 等虚拟与临时目录。重载页面或点「重置内核」后自动恢复：

```python
import os
os.mkdir('/data')                             # 在根目录建子目录
open('/data/a.txt', 'w').write('你好')         # 文本
open('/flash/b.bin', 'wb').write(bytes([0, 1, 255]))  # 二进制
print(os.listdir('/data'))                    # ['a.txt']
```

- 每次运行代码（含 REPL 单条命令）后自动回写快照；删除文件同样会同步，不会在重载后「复活」。
- 文件内容以标准 Base64 存入，二进制安全；空目录也会保留。
- 顶栏「检查更新 / 更新到本地 / 主题切换」三个按钮紧随「就绪」之后；主题按钮**只显示图标**，其后是布局切换与**文件列表开关**按钮；选项页仍保留主题切换按钮，两处状态同步。
- 兼容旧版本仅含 `/flash/...` 的快照格式；若 localStorage 配额不足，终端会给出警告。

### 多文件编辑器与文件列表

- 内核启动后默认挂载到根目录 `/`（`os.getcwd()` 为 `/`），相对路径 `open('x.py')` 即落在此处；`/flash`、`/lib` 自动创建并加入 `sys.path`。
- **启动自动运行**：若 `/flash/main.py` 存在，页面加载 / 重建内核后会自动执行它（首次运行会用编辑器初始代码创建该文件）。
- **文件列表位于工作区最左侧**，纵向跨越编辑器与 REPL 全高；右侧的竖向分隔条可拖拽调整宽度（双击复位，宽度本地保存）。
- 列表显示当前目录内容：点击文件夹进入、左上角 `←` 返回上级；头部 `＋` 在当前目录**新建文件**（立即落盘），旁边的文件夹图标**新建文件夹**。
- **鼠标右键点击文件**弹出菜单：**新建文件夹**（在当前目录）、改名（同步已打开的标签）、删除、属性（大小 / 修改时间）、下载文件；**文件夹同样可改名 / 删除**（递归删除其中全部内容，自动关闭相关标签），但不能下载。文件列表项右侧的 `×` 可直接删除文件 / 文件夹。
- 编辑器支持多文件标签页，标签上的 `●` 表示未保存；文件名后紧跟**保存按钮**，在改动后可点、未修改时置灰，等价于 `Ctrl/⌘ + S`；新增运行按钮（▶），点击即运行当前文件，和按下 `Ctrl/⌘ + Enter` 效果等同。
- 点击示例菜单会统一在 **`/flash/demo.py`** 中打开示例代码（复用同一文档，不会反复新建文件造成标签堆积），也不覆盖其它正在编辑的文件。
- 顶栏文件按钮可显示 / 隐藏左侧文件列表，状态本地保存。
- 文件列表分隔条与「编辑器 / REPL」分隔条**宽度统一**，风格一致，均可拖拽调整、双击复位。
- REPL 输入框提示包含 `↑/↓ 历史 · Ctrl-D 复位`；按 `Ctrl/⌘ + D` 执行**软复位**（重置内核、清空 Python 全局状态，类似 MicroPython REPL 的 Ctrl+D）；启动后仍会重新自动运行 `/flash/main.py`。
- 终端输出与代码区标记为**不可被浏览器翻译**，避免翻译插件把程序输出改成全角标点、出现"输出两次"的假象。
- 工具箱标签切换在 `<head>` 提前注册，**内核加载期间**也能立即切换到其它标签页。
- **代码助手**：编辑器内按 `Alt + /` 或 `Ctrl/⌘ + Space` 唤出模板浮层，继续输入关键字过滤（键名/中文名均可），`↑↓` 选择、`Tab` / `回车` 插入；内置 34 个模板。

### 计算工具

「计算」标签页内置「进制转换」「校验」「时间」三个子工具，均即时计算、无需联网：

- **进制转换**：在**输入数据**中输入待转换数据，支持 `0x`/`0b`/`0o` 前缀、下划线与任意大整数（BigInt）。**输入整数按整数转换，输入含小数点的浮点数按浮点转换**（分数部分用精确分数运算，循环小数最多展开 40 位，如 `0.1`(10)→`0.0001100110011…`(2)）。在**下拉框**选择 **2–36 全部进制**，一键交换来源/目标进制，输入时自动转换。
- **CRC 校验**：支持位宽 **4–128** 的CRC校验，可从 22 种常用模式（CRC-4/ITU、CRC-8/MAXIM、CRC-16/ARC、CRC-16/MODBUS、CRC-32、CRC-32C、CRC-64/ECMA-182 等）一键填充参数，也可自定义多项式（HEX）、初始值、结果异或值，并切换输入/输出翻转。数据支持 **HEX 模式**（每两字符一字节）与 **字符串模式**（UTF-8 编码），结果同时给出十六进制与十进制。
- **校验和**：对同一份待校验数据计算 10 种常用校验和——8/16 位累加和、异或（XOR）、纵向冗余校验（LRC）、NMEA-0183、Adler-32、Fletcher-8/16/32、BSD 校验和。
- **文件校验**：支持一次选择 / 拖入**多个文件**，本地计算 **CRC32 / MD5 / SHA-1 / SHA-256 / SHA-512**，以表格展示文件名、大小与各摘要值；文件不上传，全部在浏览器内完成。
- **时间**：两个独立时间框，标签前各有一个 **📅 按钮**，点击弹出**日历时间选择器**，确定后以 `YYYY-MM-DD HH:MM:SS` 填入对应输入框。支持多种输入格式——Unix 时间戳（秒 / 毫秒）、ISO 8601（含 `Z` / `±HH:MM` 时区）、常规日期时间 `YYYY-MM-DD` / `YYYY/MM/DD`、纯时间 `HH:MM`、中文日期 `2024年1月15日`、RFC 2822 / 英文日期，以及 `now` / `今天` / `明天` / `昨天` 等相对时间。主输入框下方有**多格式互转区**，以及**详细时间信息**。

### 点击结果自动复制

「计算」工具中点击进制转换结果、CRC 结果、校验和、文件摘要或时间详情会复制到剪贴板。选项页的**「点击结果自动复制」**复选框可关闭此行为，**默认开启**，设置即时生效并持久保存。

### 数据导入 / 导出

选项页底部的「导出数据」与「导入数据」用于整体备份 / 恢复：
- **导出**：把所有 `mp_` / `mp-` 前缀的 localStorage 与 Cookie 参数（主题、标签样式、布局方向、文件列宽、REPL 历史及保留条数、打开的文档、各游戏进度、知识库总分等）连同整个文件系统快照打包为 JSON 文件下载，文件名为 `mpy_toolbox_` + 日期 + `_` + 时间 + `.json`（如 `mpy_toolbox_20260101_123045.json`）。导出结果的提示卡片为全局组件，在任意标签页均可看到，并在 3 秒后自动消失。
- **导入**：校验备份格式后覆盖当前全部参数与文件系统文件，二次确认并自动重新加载页面，使文件系统重新挂载生效。

### 右键菜单

整个页面已屏蔽浏览器原生右键菜单，按所在组件显示对应菜单：
- **文件列表**：新建文件夹、改名、删除、属性、下载文件（见上文）。
- **编辑框 / REPL**：撤销、重做、剪切、复制、粘贴、全选。
- **终端输出**：复制选中、复制全部输出、清空输出、聚焦输入。
- **文件标签**：打开、保存、关闭、关闭其他。
- **其他页面 / 组件**：复制选中文字、切换主题、显示 / 隐藏文件列表、切换布局、重新加载页面。

## 升级方式

应用提供两条升级通道：

**1. 检查并更新内核（推荐）**

- 点击工具栏「更新」按钮，程序会从 npm registry（含镜像）检测 MicroPython 内核最新版本。
- 确认后逐文件下载 `wasm` 与 `mjs`，HTTP 模式由 `update.php` 代理、file 模式由浏览器直接下载。
- 支持 4 个 CDN 自动回退：`jsdelivr`、`fastly`、`unpkg`、`jsdmirror`；若自动下载被拦截，还提供手动下载链接。

**2. 升级程序本体**

- 程序版本号集中在配置区的 `const APP_VERSION`（单一修改点），显示于「关于」框正文。
- 请到 [GitHub](https://github.com/shaoziyang/MicroPythonPlayground) 或 [Gitee](https://gitee.com/shaoziyang/MicroPythonPlayground) 下载最新版主页面，替换旧文件即可。

> 配置区位于文件末尾，集中了 `APP_VERSION`、`SAMPLE_GROUPS`（示例菜单）、`USEFUL_LINKS`（常用链接），修改后刷新页面即生效，无需改动其它代码。

## WorkBuddy 开发过程

### 版本号规则

格式为 `主版本.次版本.build`，单一修改点为配置区 `const APP_VERSION`（显示在「关于」框）。

| 段     | 名称      | 递增规则                                  |
| ----- | ------- | ------------------------------------- |
| 第 1 位 | 主版本号    | **人工指定**，仅在明确要求时变更，不自动递增              |
| 第 2 位 | 次版本号    | 本轮有**较大功能增加**时 +1，否则不变                |
| 第 3 位 | build 号 | **每次修改都 +1**；主版本 / 次版本变化时**不归零**，继续累加 |
